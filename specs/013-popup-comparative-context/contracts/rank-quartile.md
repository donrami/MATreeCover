# Contract: Rank and Quartile

Feature 013, FR-009, FR-010, SC-003. The district rank and quartile band are the
comparative heart of the district popup. This contract fixes the algorithm, the band
formula, the reference table, and the automated cross-check.

## Algorithm (R-2, deterministic)

Input: the 38 district features from `dist/stadtteile.geojson` (or the fetched
`stadtteile.geojson` bundle file).

1. Keep districts with `mean_value != null`.
2. Sort by `mean_value` **descending**, then `name` **ascending** (tie-break, FR-009).
   JS `<` on strings (UTF-16 code units) and Python `<` (code points) order all 38 names
   identically — all names are BMP with single-code-point umlauts. This is the
   reproducibility contract between the JS implementation and the Python reference.
3. Assign sequential ranks 1..N. Tied means get **distinct** ranks (alphabetical).
4. Quartile band from rank and N (FR-010; proportional for N != 38, per Assumptions):

   ```
   q1 = ceil(N / 4)
   q2 = floor(N / 4)
   q3 = floor(N / 4)
   band 1 (oberstes Viertel):   rank <= q1
   band 2 (oberes Mittelfeld):  rank <= q1 + q2
   band 3 (unteres Mittelfeld): rank <= q1 + q2 + q3
   band 4 (unterstes Viertel):  otherwise
   ```

   For N = 38: 10 / 9 / 9 / 10 → 1-10, 11-19, 20-28, 29-38.

5. Fewer than two valid means ⇒ no rankings (rank/quartile hidden everywhere).

Labels: "oberstes Viertel", "oberes Mittelfeld", "unteres Mittelfeld", "unterstes
Viertel" (FR-010).

## JS implementation contract

Top-level, pure function in `src/site/main.js` (no map/DOM access):

- `computeDistrictRankings(districtFeatures)` → `Map` keyed by `code` with values
  `{ rank, quartile }` (quartile as band index or label — one representation, fixed in
  implementation). Exposed on `window.__districtRankings` as a debug handle, consistent
  with the existing `window.__map` / `window.__renderCityPanel` pattern.
- Called once at map load from `loadDistrictRankings()`: `fetch('stadtteile.geojson')`
  (browser-cached; same URL as the style source) → compute → store module-level.
  Failure ⇒ `null` (rank/quartile hidden).

## SC-003 automated cross-check (`tests/acceptance/test_rank.py`)

1. Python reference: recompute ranks/quartiles from `dist/stadtteile.geojson` with the
   algorithm above; assert ranks are exactly 1..38, band bounds hold, and the two known
   ties order alphabetically.
2. JS cross-check: load `dist/main.js` in a node VM (stubs: `window.maplibregl` /
   `window.pmtiles` no-op classes, `document.getElementById` → null, `window.matchMedia`
   → `{matches: false}`, `console`), call the top-level `computeDistrictRankings` from
   the VM global with the same features, and assert all 38 ranks + quartiles match the
   Python reference. Skips when node or `dist/main.js` is missing (existing dist-fixture
   pattern).

Asset: `verification/stadtteile.geojson` (38 districts, geometry only) is the SC-003
source of truth for the district set; stats are read from the published
`dist/stadtteile.geojson`.
