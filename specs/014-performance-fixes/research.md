# Research — Performance Fixes (spec 014)

Audit evidence: `validation/perf-audit-2026-08-08.md`. Scope: `spec.md`.

## R1 — Cloudflare Workers static asset caching

Observed on the live site: `cache-control: public, max-age=0, must-revalidate` plus ETag on index.html, main.js, style.css, style.json. This is the documented default for Workers static assets (developers.cloudflare.com/workers/static-assets/headers/), not a custom setting. The ETag makes revalidation cheap, but every visit still issues conditional requests.

Decision: serve content-hashed filenames and override Cache-Control to `public, max-age=31536000, immutable` for hashed files.

Rationale: hashed filenames make long-lived caching safe. Deploys are atomic (worker version switch), so the HTML never references a stale hash.

Alternatives considered:

- `_headers` file in the assets directory. Rejected: the docs state custom headers in `_headers` are not applied to responses generated by Worker code. Our worker serves assets through `env.ASSETS.fetch`, so the worker must set the headers itself.
- Fingerprinting via query strings (`main.js?v=123`). Rejected: query strings complicate CDN cache keys and are worse practice than filename hashes.

Design: the worker wraps the ASSETS response. It sets Cache-Control when the filename matches `-[0-9a-f]{12}\.(js|css|json|geojson|svg)$`. index.html and other un-hashed files keep the default revalidate policy.

## R2 — Caching of PMTiles range responses

Observed: both pmtiles objects carry `cache-control: no-store, no-transform` (scripts/deploy-cf.sh lines 91-92). No browser cache, no edge cache.

Decision: upload with `cache-control: public, max-age=86400, stale-while-revalidate=604800, no-transform`. Keep `no-transform` (Cloudflare must not alter the binary or the Range contract).

Rationale: browsers cache 206 partial responses when the response carries cacheable headers (RFC 7233). pmtiles.js issues identical ranges on repeat visits and re-pans. Browser caching alone delivers the repeat-visit win.

Edge-cache caveat (documented, empirical): Cloudflare's Workers Cache docs state a Worker-generated 206 is treated as uncacheable. The zone CDN's range caching varies by file type and zone settings (support doc: "caching behavior may vary"). Edge caching of the 206 responses is therefore NOT guaranteed. The spec's fallback applies: if a repeated range request does not return cf-cache-status HIT, SC-004 is adjusted to browser-only caching. The browser win is unaffected.

Alternatives considered: have the worker return 200 and let Cloudflare slice. Rejected. A 16 KB tile request would stream the full 34-80 MB archive from R2.

## R3 — MapLibre fadeDuration

The vendored maplibre-gl.js 5.7.1 contains the option key and the default `fadeDuration: 300`. The Map constructor accepts `fadeDuration: 0`.

Decision: set `fadeDuration: 0` in the Map constructor in src/site/main.js.

Rationale: removes the cross-fade render pass during the initial render and zoom transitions. Fill layers and the raster basemap render directly. No layout or data change.

Visual note: during zoom the basemap tiles swap instantly instead of cross-fading. This is intended. The acceptance scenario US2-S4 covers it.

## R4 — Low-zoom building geometry (tippecanoe)

Current target (Makefile `pmtiles-buildings`): `--minimum-zoom 10 --maximum-zoom 18 --base-zoom 14 --drop-densest-as-needed --extend-zooms-if-still-dropping --read-parallel`.

tippecanoe 2.80.0 (installed) flags:

- `-S <scale>` / `--simplification=<scale>`: multiplies the simplification tolerance. The README says a scale up to about 10 has little visible difference.
- `-pS` / `--simplify-only-low-zooms`: does not simplify at the maximum zoom, but does simplify lower zooms.

Decision: add `-S 10 --simplify-only-low-zooms` to the buildings target.

Rationale: feature presence is controlled by `--drop-densest-as-needed`, which stays unchanged. Feature count per tile therefore stays identical. Vertex density drops, which is the main-thread cost at the city-scale initial view (12,570 rendered buildings). z18 is untouched.

Parity constraint: the acceptance gates (feature-count parity per tile, screenshot diff at z10/z12/z14/z16/z18) bound the tuning. If -S 10 fails the visual parity gate, drop to a lower scale. The implementation tunes within these gates.

Alternatives considered: raising `--drop-rate` to drop more buildings at low zooms. Rejected. It removes features. That violates the no-missing-buildings gate (SC-006).

## R5 — Publish-time hashing

`src/pipeline/publish.py` copies STATIC_FILES from src/site/ to dist/ and writes dist/manifest.json. It is the single place that emits the bundle.

Decision: add a deterministic post-process step in publish.py that hashes files, renames them, and rewrites references.

Files hashed (sha256, first 12 hex chars):

- main.js, style.css, style.json
- vendor/maplibre-gl.js, vendor/maplibre-gl.css, vendor/pmtiles.js
- stadtteile.geojson, boundary.geojson
- new favicon.svg (un-hashed, referenced by name)

Reference rewrites:

- index.html: script srcs, the new preload href, inline CSS, preconnect, favicon link
- main.js: `STYLE_URL` constant (style.json) and the fetch URLs for stadtteile.geojson and boundary.geojson
- style.json: `data` URLs for the two geojson sources

Rationale: stadtteile.geojson (120 KB transfer) is the largest text asset revalidated per visit. Hashing it closes the revalidation loop: index.html becomes the only revalidated file.

Alternative considered: hash only main.js, style.css, style.json, vendor files. Rejected. It leaves two revalidation round trips per visit for the geojson sources. That is the same bug class we are fixing.

## R6 — Critical-path changes (index.html)

CSP already permits every change: style-src 'unsafe-inline' (inline CSS), img-src 'self' data: (favicon), connect-src includes sgx.geodatenzentrum.de (preconnect), script-src 'self' (preload of the self-hosted vendor script).

Decision:

- Inline style.css and vendor/maplibre-gl.css into a `<style>` block in the head at publish time. Removes both render-blocking stylesheet requests.
- Add `<link rel="preconnect" href="https://sgx.geodatenzentrum.de">`.
- Add `<link rel="preload" href="vendor/maplibre-gl-<hash>.js" as="script">` so the 248 KB download starts before the parser reaches the end-of-body script.
- Add `<link rel="icon" type="image/svg+xml" href="favicon.svg">` and ship a small self-hosted favicon.svg.
