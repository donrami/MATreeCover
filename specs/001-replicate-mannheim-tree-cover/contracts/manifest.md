# Contract: `artifacts.manifest.json`

The single source of truth for what the pipeline reads, what it
reuses, and what it invalidates. Lives in the repo root. The
pipeline is the only writer; acceptance tests assert it.

## Schema

```jsonc
{
  "release_id": "2026.01",
  "generated_at": "2026-08-03T00:00:00Z",
  "artifacts": [
    {
      "path": "boundary.geojson",
      "kind": "boundary",
      "size_bytes": 148000,
      "sha256": "…",
      "source": "LGL, dl-de/by-2-0",
      "license": "dl-de/by-2-0",
      "extent": { "type": "Polygon", "coordinates": [ … ] },
      "resolution": "n/a",
      "completeness": 1.0,
      "lineage": { "inputs": [] },
      "acceptance": "pass",
      "checks": {
        "source":       "ok",
        "extent":       "ok",
        "resolution":   "ok",
        "completeness": "ok",
        "lineage":      "ok"
      },
      "invalidates": []
    },
    {
      "path": "mosaic/canopy_prediction_mask.tif",
      "kind": "canopy-mask",
      "size_bytes": 232000000,
      "sha256": "…",
      "source": "mannheim pipeline, deepLabV3plus-resnet34",
      "license": "MIT",
      "extent": { "type": "Polygon", "coordinates": [ … ] },
      "resolution": "0.2 m",
      "completeness": 0.48,
      "lineage": { "inputs": ["imagery-tile-hashes"] },
      "acceptance": "fail",
      "checks": {
        "source":       "ok",
        "extent":       "ok",
        "resolution":   "ok",
        "completeness": "fail",
        "lineage":      "ok"
      },
      "invalidates": ["buildings.geojson", "trees.pmtiles"]
    }
  ]
}
```

## Field rules

- `path` is workspace-relative. Use forward slashes.
- `size_bytes` is the on-disk size. Files > 50 MiB are still
  recorded here; they just stay out of git history (OR-005).
- `sha256` is the SHA-256 of the file at the time of
  acceptance. The pipeline re-hashes the file on every `accept`
  run.
- `source` is a human-readable origin string.
- `license` is `"dl-de/by-2-0"` for LGL data, `"MIT"` for
  derived code, or the run's own licence for derived rasters.
- `extent` is the polygonal coverage of the artifact.
- `resolution` is the GSD for rasters; `"n/a"` otherwise.
- `completeness` is the fraction of the buffered boundary
  covered by this artifact, in `[0, 1]`. The acceptance
  threshold is `>= 0.95` (matches `meta.json.coverage_ratio_min`).
- `lineage.inputs` is a list of input artifact paths or hashes.
- `acceptance` is `"pass"`, `"fail"`, or `"pending"`.
- `checks` carries the per-criterion status (`"ok"` or
  `"fail"`). The five criteria are the FR-021 list.
- `invalidates` is the list of dependent artifacts that must
  be marked `"pending"` if this one is `"fail"`.

## Acceptance state machine

```text
                 ┌─ pass ─────► pass
                 │
  pending ───────┼
                 │
                 └─ fail ─────► fail ──► (cascades to invalidates)
```

`pass` is terminal. `fail` cascades to its `invalidates` list on
the next `accept` run; the maintainer may also re-run the failed
job once it has new inputs (e.g. a RunPod-produced canopy mask).

## Rules for the pipeline

- Before reading any artifact, the pipeline looks up its
  `acceptance`. A `pending` or `fail` short-circuits the
  subcommand.
- A `pass` artifact is read but never re-generated by the
  pipeline (FR-022).
- The pipeline writes a new `artifacts.manifest.json` after
  every `accept` and `publish` run.
- The pipeline never edits an artifact's bytes in place. New
  outputs get a new path and a new manifest entry.
