# UX Audit — Baumfläche Mannheim (MATreeCover)

- **Date:** 2026-08-09
- **Target:** https://abu-hamad.de/map/ (live production)
- **Method:** ux-audit skill workflow — persona-locked walkthrough, interaction manifest, keyboard pass, axe-core 4.10.2, viewport matrix (1440×900, 375×667, 320×568), stress battery, vision-verified screenshots
- **Environment:** headless Chromium (shared browser + system chromium cross-check); console/network capture on every pass
- **Mode:** read-only. No code was changed.

## Verdict

**PASS — ship-state quality. No Critical or High findings.**

The app is unusually solid for a hobby-scale data map: zero console errors, zero network failures on all normal loads, fully keyboard-accessible modal with focus trap, persisted first-visit onboarding, correct ARIA throughout, no horizontal overflow at 320px, no crashes under interaction spam. Six minor findings below — none block usage.

---

## Findings

### M1 — Mobile: popup bottom edge clips under the expanded bottom sheet
- **Severity:** Medium
- **Repro:** 375×667, expand the surface sheet, tap a district → popup opens behind/under the sheet's top edge; its bottom is visually cut by the sheet.
- **Evidence:** Wallstadt popup rect 240×419 at y=306 (viewport 667); vision pass confirms the popup's lower content merges into the sheet. Screenshots: `1551695d32adb951.webp`, `1551696f01edb954.webp`.
- **Impact:** On the most common mobile interaction (tap → read popup) with an expanded sheet (the default after first tap), the popup's context lines are hidden behind the sheet.
- **Fix direction:** give the popup a z-index above the sheet, or offset popup placement to clear the sheet's top edge when expanded.

### M2 — Keyboard: no Escape (or other keyboard) dismissal for map popups; close button is ~11 Tabs deep
- **Severity:** Medium
- **Repro:** click a building → popup opens; press Escape → nothing (Escape only closes the story modal). Tab from the map: canvas → zoom controls → surface controls → … the popup × is reached only after ~11 stops.
- **Evidence:** `popupAfterEsc: "flex"` (still open); source: both popups use `closeOnClick: false` with no `keydown` handler (deliberate per research R-001/R-002 — keep popup while exploring). Confirmed in `src/site/main.js`.
- **Impact:** keyboard and screen-reader users cannot dismiss a popup without tabbing deep; assistive-tech users have no announced close affordance at all.
- **Fix direction:** Escape → close popups (the research intent survives: only explicit user action closes); add `aria-label="Schließen"` (already localized) and move the × into the natural tab flow, or make the popup a `role="dialog"` with trapped focus.

### L1 — 320px (iPhone SE-class): expanded sheet clips text at the left edge
- **Severity:** Low
- **Repro:** 320×568, expand the sheet → tab label renders "ßume", "Durchschnittlicher Baumanteil…" and "Mannheim im Überblick" have their leading characters cut. Panel sits flush at x=0 with content wider than the box, no horizontal scroll (`scrollWidth === 320`).
- **Evidence:** vision pass on `15516a9aa92db956.webp`; `overflowX: false` in DOM probe.
- **Impact:** only 320px-class devices, only expanded state. Collapsed bar and map are fine.
- **Fix direction:** `min-width: 0`/`flex-wrap` on the sheet's inner flex rows, or a left padding that survives content overflow.

### L2 — axe: attribution link indistinguishable within its text block (serious, 1 violation)
- **Severity:** Low (single, MapLibre default styling)
- **Evidence:** axe 4.10.2: `link-in-text-block` on `.maplibregl-ctrl-attrib-inner > a[href$="attribution"]`. One `incomplete` (canvas color-contrast — untestable). Modal-open scan: identical single violation; the modal itself is axe-clean.
- **Fix direction:** underline or weight the "Datenquellen" attribution link.

### L3 — Building popup value formatting inconsistent with district popup
- **Severity:** Low
- **Evidence:** building popup shows "Baumanteil im 60-m-Umkreis **3.69%**" (2 decimals, no space); district popup "**17.3 %**" (1 decimal, thin space). Source: building value uses a raw 2-decimal `value` string; district uses `formatPercent` (`toFixed(1)`).
- **Fix direction:** route the building headline through the same formatter for one decimal + space.

### L4 — Rapid zoom spam triggers external-tile HTTP 400s (self-healing)
- **Severity:** Low
- **Evidence:** 49 × HTTP 400 from `sgx.geodatenzentrum.de/wmts_basemapde/...` during machine-paced zoom spam (10× in/out with no pause). Moderate zooming (250 ms between clicks): **zero** 400s. Map recovers after settling — no error state, no crash.
- **Impact:** none for real users (human clicking is >250 ms); transient blank tiles only under pathological input.
- **Fix direction:** none required; optionally cap zoom animation duration.

### L5 — Direct `.html` legal URLs 404 into the parent site's theme
- **Severity:** Low
- **Evidence:** `/map/impressum` and `/map/attribution` → 200 (real content — all in-app links work); `/map/impressum.html` and `/map/attribution.html` → 404 served by "Rami's Sandbox" WordPress theme. Canonical/robots presumably reference the extensionless forms.
- **Impact:** only hand-typed or legacy-bookmarked `.html` URLs.
- **Fix direction:** Worker fallback mapping `*.html` → extensionless route.

## Self-critique (limitations)

- **Headless WebGL presentation artifact** delayed visual verification: tiles fetched 200 but canvas composited black in this environment until several seconds after load (system-chromium cross-check + modal-close A/B ruled out a site defect; the map renders correctly once settled — author-confirmed). Pixel `readPixels` probes were invalid (canvas uses `preserveDrawingBuffer: false`); all color/rendering conclusions come from composited screenshots, not GPU reads.
- Screenshot review is vision-model based; element coordinates in vision passes carry ±few-px uncertainty (mitigated by DOM rect probes for all critical geometry).
- The tile-400 stress used machine-paced clicks (~50 ms apart), faster than any human input.
- No real-device touch testing; synthetic pointer events only.
- Accessibility was automated (axe) + manual keyboard; no screen-reader (NVDA/VoiceOver) session run.
